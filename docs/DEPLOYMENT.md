# Future deployment: Vercel (web) + Render (API) + Neon (PostgreSQL)

Nothing in this repository is deployed. These are the steps to deploy when ready.

## Recommended topology

```
Browser ──https──> Vercel (static React app)
                      └── /api/*  rewrite ──> Render web service (Express API) ──TLS──> Neon PostgreSQL
Extension ──https──> https://<your-vercel-domain>/api/ext/*   (bearer token)
```

The Vercel rewrite keeps the API same-origin with the web app, so the session cookie is first-party (`SameSite=Lax`, `__Host-` prefix) and CORS is not needed. Without the rewrite, set `COOKIE_SAMESITE=none`, `COOKIE_SECURE=true`, add the web origin to `WEB_ORIGIN`, set `VITE_API_BASE_URL`, and update the CSP `connect-src` in `vercel.json`.

## 1. Neon (database)

1. Create a project and database `footprintx` (free tier is sufficient to start).
2. Copy the **pooled** connection string (`...-pooler...neon.tech/footprintx?sslmode=require`).
3. Migrations run automatically when the API starts (`apps/api/migrations`, advisory-locked). To run them manually: `DATABASE_URL=... DATABASE_SSL=true npm run db:migrate -w apps/api`.
4. Never run `db:seed` against production (it refuses when `NODE_ENV=production`).

## 2. Render (API)

1. New → Blueprint → select this repository; `render.yaml` defines the `footprintx-api` web service (free plan).
2. Fill the `sync: false` variables: `DATABASE_URL` (Neon), `WEB_ORIGIN` (e.g. `https://footprintx.vercel.app`), `API_PUBLIC_URL` (the **web** origin when using the rewrite, so OAuth redirects go through it), `CONTACT_RECIPIENT`.
3. `TOKEN_ENCRYPTION_KEY` is generated by Render; copy it to a safe place (see SECURITY.md → key management).
4. Email: set `EMAIL_PROVIDER=smtp` and `SMTP_HOST/PORT/USER/PASS`, `EMAIL_FROM` (any SMTP provider; several have free tiers). With `none`, the app clearly reports that email is not configured.
5. Health check: `/api/health`. `TRUST_PROXY=true` is set so rate limits see client IPs.
6. Free-plan limits: instances sleep after inactivity (first request is slow; in-flight scans stop if the instance sleeps), and cron jobs are paid. The API refreshes threat feeds and the breach catalogue hourly while awake. For notification jobs without paid cron, run `npm run jobs:notify:prod -w apps/api` from any scheduler that can reach the database (e.g. a scheduled GitHub Actions workflow with `DATABASE_URL` as a secret).

## 3. Vercel (web)

1. Import the repository; set **Root Directory** to `apps/web`. Build command `npm run build`, output `dist` (already in `vercel.json`).
2. Edit `apps/web/vercel.json`: replace `REPLACE-WITH-YOUR-RENDER-SERVICE.onrender.com` with your Render hostname.
3. Security headers (CSP, HSTS, frame denial, referrer and permissions policies) are applied by `vercel.json`.

## Email OAuth setup

### Google (Gmail)
1. Google Cloud Console → create project → enable **Gmail API**.
2. OAuth consent screen: External; scope `https://www.googleapis.com/auth/gmail.metadata` only.
3. Credentials → OAuth client ID (Web). Authorized redirect URI: `${API_PUBLIC_URL}/api/connections/oauth/google/callback` (locally: `http://localhost:4000/api/connections/oauth/google/callback`).
4. Set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. While the app is in "Testing", only listed test users can connect.
5. **Before public launch:** `gmail.metadata` is a *restricted* scope; Google requires app verification and may require an annual third-party security assessment (CASA), which can have a cost.

### Microsoft (Outlook / Microsoft 365)
1. Microsoft Entra admin center → App registrations → New registration; supported account types: personal + work/school (tenant `common`).
2. Redirect URI (Web): `${API_PUBLIC_URL}/api/connections/oauth/microsoft/callback`.
3. API permissions (delegated): `User.Read`, `Mail.ReadBasic`, `offline_access`. Create a client secret.
4. Set `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET`, `MICROSOFT_TENANT=common`.
5. Publisher verification is recommended before broad release.

## Threat-intelligence providers

| Provider | Cost / terms | Configure |
|---|---|---|
| Phishing.Database feed (default) | Free, MIT | `THREAT_FEED_URLS` |
| Look-alike heuristics | Built in | `heuristics` |
| abuse.ch URLhaus | Free Auth-Key (https://auth.abuse.ch/) | `URLHAUS_AUTH_KEY` + add `urlhaus` |
| Google Safe Browsing v4 | Free key, **non-commercial** use only | `GOOGLE_SAFE_BROWSING_KEY` + add `safebrowsing` |

Optional per-email breach lookups need a paid HIBP key (`HIBP_API_KEY`); without it, FootprintX shows service-level breach matches only and says so.

## Browser extension release

1. Build against production: `NODE_ENV=production FOOTPRINTX_API_URL=https://<vercel-domain> FOOTPRINTX_WEB_URL=https://<vercel-domain> npm run package -w apps/extension` (the build refuses non-HTTPS URLs in production mode).
2. Upload `apps/extension/packages/footprintx-extension-<version>.zip` to the Chrome Web Store (one-time developer registration fee) and/or Microsoft Edge Add-ons (free).
3. Store review: justify `webNavigation` (automatic checks of top-level navigations) and the single host permission; publish a privacy policy URL (the web app's `/privacy`); complete the data-use disclosure ("website hostnames, not content; warning events only with opt-in").
4. Bump `version` in `apps/extension/package.json` for each release.

## Billing (not implemented)

Premium is currently granted only by the development entitlement switch, which is disabled in production. To sell Premium later: integrate a payment provider (e.g. Stripe Checkout + Customer Portal), verify webhook signatures, process events idempotently (store event IDs), handle the full subscription lifecycle (trial, active, past_due, canceled), reconcile periodically against the provider, and set `users.plan`/`plan_source='billing'` only from verified server-side events. Never grant Premium from a client redirect.

## Production checklist

- [ ] `NODE_ENV=production`, `COOKIE_SECURE=true`, `TRUST_PROXY=true`, `DATABASE_SSL=true`
- [ ] Dev switches off (the API refuses to start otherwise)
- [ ] `TOKEN_ENCRYPTION_KEY` stored securely
- [ ] SMTP configured and `CONTACT_RECIPIENT` set
- [ ] `npm run links:verify -w apps/api` passes from an unrestricted network
- [ ] Address open items in SECURITY.md (email verification, MFA for FootprintX logins, shared rate-limit store)
- [ ] Privacy notice reviewed by counsel for your jurisdiction (backup retention window, contact address)
